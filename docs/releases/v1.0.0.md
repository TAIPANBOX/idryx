# Idryx 1.0.0

The identity plane of the TAIPANBOX stack: read-only connectors stitch humans,
service accounts, keys, MCP servers and AI agents into one identity graph, and
27 deterministic detectors say what is over-privileged, anomalous or unowned.
It observes; remediation is a proposal a human applies.

## What 1.0 promises

`compat/1.0.json`, rendered as `COMPATIBILITY.md` and held by
`scripts/compat-surface.sh` on every push: the eight subcommands (`detect`,
`bom`, `ai-inventory`, `serve`, `load`, `remediate`, `ebpf-capture`,
`version`), the sink-delivery exit code 3, the four `serve` routes, the three
`IDRYX_` environment names, the `identity_finding` event this plane emits, the
ten bus event types it reasons about, and CycloneDX 1.6 for the Agent-BOM. A
frozen name is not removed or renamed within this major; a new detector is a
new finding, never a removed one. Support line: the newest minor gets every
fix; the previous minor gets security-relevant fixes for 90 days after the
newer one is tagged.

## Since 0.3.1

- `ai-inventory`: where the estate uses AI models, across three sources
  (Passport-declared, observed egress, a qryx code scan), a report that names
  disagreement and never scores it (#53, #52).
- Detectors: `claimed_agent_unattested`; a claim arriving by bus is still a
  claim (#47, #46); the observed provider carries a registered id, not a
  display name (#50).
- The eBPF sensor: "self" is decided by the tgid the sensor's own PID
  namespace assigns (#69); a provider address wears its hostname only on port
  443, so a DNS lookup is never an LLM call (#68, #71); the sensor reads the
  kernel's own copy of the address and the caller's length, from a kprobe on
  `__sys_connect_file`, and builds for amd64 and arm64 only (#77); the
  committed BPF object is proven to be what the committed C compiles to (#73).
- `components.json` declares the `idryx-detect` routine and the
  `IDRYX_EVENTS`/`IDRYX_TRUST_DOMAIN` pairing, and a test proves both (#55).
- `agent-stack-go` v1.0.0, the contract at 1.0 (#79); Go 1.27 (#57).
- Every release is signed, attested and carries SBOMs (#80); workflows run
  read-only except where they publish (#83), actions are pinned to commits
  (#63), and an OpenSSF Scorecard is published (#65).

## Proven, by the 1.0 proving run (estate-gates `PROVEN.md`, section "The 1.0 proving run")

The run exercised the shipped 0.3.x artifacts on live rigs; 1.0.0 is main
after them. Each row names what it ran.

- **POL-4, R2 GCP** (image v0.3.0 as the cluster pinned it): `idryx detect` on
  the cluster's bus raised **613 alerts**, among them a `critical
  data_exfiltration` for the drill notetaker; `idryx bom` over the same bus
  listed **304 agents**.
- **REC-1, R2 GCP** (image v0.3.0): the `idryx-detect` routine (the cluster's
  `identity-sweep` CronJob) fired by hand ran in 3 s and raised 6 alerts from the bus.
- **INS-7, R1 GCP** (release v0.3.1 by the README's own block): tarball
  downloaded, `sha256sum -c` OK, `idryx version` answered `v0.3.1`, and
  `idryx detect` on the day's real bus raised `runaway_agent`.
- **RUN-4, R0** (main at `bfd7c7b`, this tag's lineage): the bank-in-a-box
  night incident, seven-check scoreboard 7/7, Idryx's `runaway_agent` HIGH
  among them.
- **The eBPF sensor** (2026-09-08, main): attached on a LinuxKit 7.0.12
  aarch64 kernel it was never built against, reported `proc:wget` and
  `proc:nc` connections correctly and counted 36 non-INET connects it
  deliberately skipped.

## Upgrade note, 0.3.x to 1.0.0

- Postgres (`--db`): the schema is applied idempotently on every open
  (`CREATE TABLE IF NOT EXISTS`, `ALTER ... ADD COLUMN IF NOT EXISTS`), so a
  0.3.x database is migrated by the first 1.0.0 command that opens it. Nothing
  to run by hand. A replayed source file stays idempotent (natural key on
  events).
- The bus: 1.0.0 emits the same `identity_finding` under the same schema
  versions (v0.2 for an established subject, v0.3 for a claimed one) and reads
  the same ten types. Nothing a consumer parses moved.
- The eBPF sensor now needs Linux 5.7 or newer (`bpf_get_ns_current_pid_tgid`)
  on amd64 or arm64. A 0.3.x sensor inside a container compared the wrong PID
  namespace and reported its own traffic as external (issue #66); 1.0.0 gets
  that right, and on an older kernel refuses to load and says why rather than
  running a filter that matches nothing.
- Release asset names carry no version, as before; `idryx version` carries it.
- `ai-inventory` is new since 0.3.0 and additive; every 0.3.x invocation runs
  unchanged.

## Not in this release, said plainly

- The eBPF sensor has never run on a real fleet or a real cloud host, and has
  been measured live only on aarch64; x86_64 is built and gated, not run.
- The three-source `ai-inventory` did not run on a deployed stand in the
  proving run: the clusters pinned 0.3.0, which does not have it.
- Detection determinism (same graph in, same findings out) is a design rule
  held by review, not by a gate.
- The dashboard HTML and the egress log JSON `ebpf-capture` writes are
  experimental in `compat/1.0.json` and may change in a minor.
