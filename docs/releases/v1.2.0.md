# Idryx 1.2.0

A TokenFuse line in `tokenfuse-openai.ndjson` is now ingested into the identity graph as TokenFuse. Before this release that file was refused as a foreign source, so the agents of a second TokenFuse gateway (the OpenAI wire, `TOKENFUSE_WIRE=openai`) never reached the graph.

## What 1.2 changes, and what it leaves frozen

`compat/1.0.json` is unchanged in its `frozen` lists, and `scripts/compat-surface.sh` holds that: no subcommand, exit code, route, frozen environment name, emitted or consumed event type or format moved. No environment variable was added. It is a minor and not a patch because a file that 1.1 refused is now read.

## Since 1.1.0

- **The second TokenFuse gateway's file is ingested as TokenFuse** (#100). `tokenfuse-openai.ndjson` joins `tokenfuse-cloud.ndjson` and `tokenfuse-mcp.ndjson` in the exception table of `internal/ingest/stream`. A line in that file that claims another source is still refused, counted, and named on stderr. The change has one behavioural test in `cmd/idryx/source_test.go` and one scenario in `features/source-must-match-its-stream.feature`.
- **Go 1.27.2** (#95). The `go.mod` toolchain, the CI `go-version`, the release workflow's build job and the Dockerfile's Go argument move together. Go 1.27.0 and 1.27.1 carry nine standard-library vulnerabilities (GO-2026-6603 to GO-2026-6617, in net/http, HTTP/2, net/textproto and crypto/tls), all fixed in 1.27.2. This release is built with 1.27.2.
- **agent-stack-go v1.1.0** (#93), from v1.0.2. The library API is unchanged. The minor adds the agent-conform CLI and image, which this binary does not use.
- **CI: the estate secret scan** runs on every pull request and on every push to `main` (#96). It is a job that calls the estate's reusable scanner. No runtime change.
- **Documentation and comments only** (#94, #98, #99, #101). The README's layout block names `internal/ingest/stream` and the `ai-inventory` command. The README's connector list, sensor description, direct-dependency count and port-443 hostname rule now match the code, and the dated prices are marked as not re-checked. Two code comments name the passport and agent-event versions the pinned module accepts. The decision notes in `release.yml`, `AGENTS.md` and `internal/events` are paraphrased rather than quoted.

## Upgrade note, 1.1.0 to 1.2.0

- Nothing to configure. No variable was added, removed or renamed.
- A box whose second TokenFuse gateway writes `tokenfuse-openai.ndjson` gets that gateway's agents into the graph after this release. A gateway that writes under another name still needs a rename, or a declaration in `IDRYX_STREAMS`, as in 1.1.
- Asset names still carry no version (`idryx_<os>_<arch>` archives), and the version is stamped into the binary. The image is `ghcr.io/taipanbox/idryx:v1.2.0`; the tags stay immutable.

## Evidence and limit

374 test functions (373 at 1.1.0). `features/source-must-match-its-stream.feature` carries 13 scenarios, each bound to a named test, with 0 broken. The new tests were run against the unfixed table first and failed there, as #100 records. That run is not repeated for this release.

## Not proven

- No live second gateway has written `tokenfuse-openai.ndjson` into an Idryx run. The producer side was read from TokenFuse 1.11.0's source, not run.
- The toolchain and dependency moves (#93, #95) were checked by CI on their own pull requests, not by a run against a deployed estate.
- The exception table is a copy that Idryx and heraldyx each carry, and nothing holds the two equal. Both carry the `tokenfuse-openai` row as of this release.
- A process that creates `tokenfuse-openai.ndjson` before the gateway does, and writes `source: tokenfuse` into it, passes, because the name and the claim agree. The same limit that 1.1 names for `wardryx.ndjson` applies. Directory ownership in the launchers and a per-file owner-uid check are not built.
- The eBPF sensor's source is unchanged since v1.1.0. `object-matches-its-source.sh`, the four BPF teeth cases and the integration job run only in CI's Linux jobs and were not run for this release.
- The release and image jobs run only on the tag push. The checks listed above were run locally, not in those jobs.
