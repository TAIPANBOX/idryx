# Idryx 1.4.0

A minor release on the 1.3 surface. `idryx ai-inventory` now says, for each agent or service, what was declared, what was seen and what the code can reach, and it names every disagreement between them. The change is additive: the schema string `idryx.ai-inventory/v1` stays, no subcommand or flag is added, and no frozen name moved, which `scripts/compat-surface.sh` holds.

## Upgrade

Nothing breaks, and an existing run needs no edit. Replace the 1.3.1 binary or image with this one. A reader of the `ai-inventory` JSON that ignores fields it does not know is unaffected by the new ones. To roll back, run the 1.3.1 binary or image again.

## What changed since 1.3.1

- **AI usage per agent or service (#119).** `idryx ai-inventory` compared three sources provider by provider. It now also reports per subject. Nothing is scored or ranked, and nothing is a detector (AGENTS.md invariant 10 stands).
  - **One row per source it was built from** (declared, bus, egress, ebpf, code). A source nobody supplied is a row that says what its absence means: code not scanned is not nothing in the code, and an absent capture is not a capture that saw nothing.
  - **One row per subject and provider**, with the disagreement named: `declared_not_seen`, `declared_bus_only`, `seen_not_declared`, `seen_no_declaration`, `declares_no_models`, `no_declaration`, and on provider rows `in_code_not_seen`.
  - **The bus names no provider.** An agent active there through an enforcement point is shown as `bus_only`, which is a different statement from not seen: a governed agent's provider connection is made by the gateway's process, where only a capture of that host sees it.
  - **The code column stays per provider for the whole estate.** A source scan finds a file and a line, and no field binds a repository to an identity.
  - **The provider vocabulary is the one `ai-inventory` already uses** (the registered id from agent-passport SPEC 4.7, lowercased and nothing else; the host matcher is `detectors.MatchLLMHost`). No second vocabulary, and no change to qryx or to any shared contract.
  - **The JSON document gains `sources` and `subjects`**, and each provider row gains `gaps`. `compat/1.0.json` lists the addition under `additive`.
  - **Monitoring limits travel with every report:** attribution is self-declared (SPEC 3.3), the eBPF sensor is Linux-only, and a process with code execution can open a socket of its own.
- **The qryx document is read as untrusted input.** At most 32 MiB, every kept string escaped and cut, at most 512 providers and 32 labels each, and a provider that is not an id is set aside and counted. Names from a Passport, a bus envelope or a capture are escaped before they reach a terminal.
- **Agreement with the detectors is held by a test.** The agents the report names `seen_not_declared` are exactly the agents `undeclared_llm` fires for, and the processes it names `seen_no_declaration` are exactly the ones `unmanaged_egress` grades as having reached a model API. `TestTheReportAgreesWithUndeclaredLLMAndUnmanagedEgress` holds the two equal.
- **Dependency and CI (#118, #117).** `agent-stack-go` moves to v2.0.2, the Go 1.27.3 rebuild, with no API change. The CI actions group is updated.

No other commit lies between the 1.3.1 tag and this release.

## Evidence

- 13 scenarios in `features/ai-usage-by-subject.feature`, each bound to a named test, and 14 new tests in all (13 scenario tests, a fuzz target and a kinds test), 417 test functions, green under `go test -race`.
- Sixteen planted faults, each caught by a named test. Two survived at first and the tests were strengthened until both were caught.
- Hostile input: qryx documents oversized, of the wrong shape, full of control bytes, with non-id providers, thousands of labels and limits, truncated at every offset, a 200-seed sweep, and a Go fuzz target (388,576 executions, no failure).
- Gate `scripts/usage-gaps-complete.sh` (invariant 19): every gap and source name has a sentence in the code and a row in the README, and the README names nothing the code lacks. Six cases in `gates-have-teeth.sh`.
- `internal/aiusage` coverage rose from 86.9% to 96.4%.
- A run on forge, linux/amd64, with a real qryx scan of a real tree (20 sites, 4 providers), a real 30 second eBPF capture (60 flows, 11 processes) and the live stack's bus files (1050 events, 66 agents).

## Limits

- The bus carries a model only in `call_retained`, which is not read here, so the report does not compare model names with anything. The egress side names a host, never a model.
- Whether an identity has a declaration is read from its source (`passport`) or from a declared model or attestation. That is a reading of the graph and not an attested fact.
